Motrix Server packages the Web UI and aria2 in a Docker container for NAS and home-server deployments. The same core that drives the desktop app on macOS, Windows, and Linux runs inside the container — downloads, sessions, plugins, and the MDXP protocol are all identical. A browser is the only client you need on day one, and the full CLI and agent ecosystem are available through device-code pairing the moment you need them.

## What You Get

- **Web UI** accessible from any browser on your local network or through a reverse proxy
- **MDXP JSON-RPC 2.0 endpoint** for CLI and agent clients — the same open protocol used by the desktop app
- **Device-code pairing** for remote CLI and agent access without storing passwords in client config
- **Non-root container with read-only root filesystem** — no privileged mode required
- **Plugin system** — the same plugins that run in the desktop app install and persist across container replacements
- **Multi-architecture** — a single image tag pulls the right manifest for `linux/amd64` and `linux/arm64`

## Image Registries

Tagged releases publish the same image to both registries. Docker Hub is the default in the included Compose files because NAS interfaces discover it with the least configuration. GHCR is a GitHub-native mirror and a useful fallback when Docker Hub is unavailable.

| Registry | Image reference |
|----------|----------------|
| Docker Hub | `docker.io/motrixapp/motrix-server` |
| GHCR | `ghcr.io/agalwood/motrix-server` |

## Image Tags

Every release publishes the same manifest digest to both registries before any floating tag is advanced. Prereleases never update `latest`, `stable`, or any floating major or minor tag.

| Tag | Behavior | Recommended use |
|-----|----------|-----------------|
| `:2.3.4` | Immutable release | Production and rollback |
| `:2.3` | Newest stable patch in 2.3 | Automatic patch upgrades |
| `:2` | Newest stable release in major 2 | Automatic minor and patch upgrades |
| `:stable` | Newest stable release | Users who explicitly want the stable channel |
| `:latest` | Same digest as `stable` | NAS UI default |
| `:2.3.4-beta.2` | Immutable prerelease | Evaluation only |

## Ports

The container exposes two independent services on separate ports. They serve different clients and require separate proxy upstreams when placed behind a reverse proxy.

| Port | Service |
|------|---------|
| `8080` | Web UI, operator API, `GET /healthz` |
| `16801` | MDXP client endpoint (`POST /mdxp`, `GET /mdxp/events`, device-code pairing) |

<Note>
  The internal aria2 RPC port (16800) is used only inside the container and is never exposed on the host. Port 16801 is the MDXP endpoint — it is not the aria2 RPC port.
</Note>

## Persistent Storage

The container root filesystem is read-only. All state lives in two writable mounts that survive container replacement. Keep them on separate backing stores so you can back up the small, consistency-sensitive `/data` tree independently of large downloads.

| Path | Purpose | Back up? |
|------|---------|---------|
| `/data` | SQLite DB, settings, aria2 session and DHT state, torrent metadata, operator token, plugin packages/state/logs, and plugin secret lockbox | Yes |
| `/downloads` | Completed and in-progress HTTP, BitTorrent, and magnet resources | According to your data policy |
